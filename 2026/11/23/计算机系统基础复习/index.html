第一章：底层执行模型与核心概念

——寄存器、内存、栈、RIP、条件码

本章是后续所有内容的基础。后续的C语句到汇编、函数调用、异常控制流、优化、链接，都会反复用到本章概念。学习目标不是背孤立名词，而是建立“CPU如何按地址取指令、如何用寄存器和内存保存数据、如何用栈维护函数调用、如何根据条件码改变控制流”的整体模型。

1. 本章学习目标

  1. CPU执行程序时，指令从哪里来？下一条指令地址由谁保存？
  2. 寄存器有哪些？不同宽度的寄存器名如何对应？
  3. 内存如何编址？地址和地址中的内容有什么区别？
  4. 什么是小端序？一个多字节数据在内存中如何排列？
  5. 栈向哪个方向增长？push/pop/call/ret对栈和寄存器做了什么？
  6. 函数调用时栈帧大致如何布局？rbp和rsp各起什么作用？
  7. 标志寄存器中的ZF、SF、CF、OF分别表示什么？
  8. cmp/test与条件跳转如何配合？
  9. 顺序执行、跳转、调用、返回、中断异常时，RIP如何变化？
  10. 常见的寄存器、内存、栈、条件码易错点有哪些？

2. CPU执行程序的基本模型

2.1 冯·诺依曼思想

核心是：

  • 存储程序：程序以指令形式存放在存储器中；
  • 程序自动执行：CPU按程序计数器指示的位置不断取指、译码、执行。

CPU执行一条指令的大致过程：

  1. 取指：根据RIP指向的地址从内存取指令；
  2. 译码：确定操作码、操作数、寻址方式；
  3. 执行：进行数据传送、运算、访存、跳转等；
  4. 更新RIP：顺序执行时RIP增加指令长度；跳转/调用/返回/中断异常时RIP被改写。

要建立的基本认识：

  • RIP决定“执行到哪里”；
  • 寄存器保存CPU当前正在处理的数据和地址；
  • 内存保存指令和数据；
  • 栈是内存中的一块区域，用来支持函数调用和局部变量；
  • 条件码决定条件跳转是否发生。

3. 寄存器体系

3.1 通用寄存器

x86-64常见通用寄存器包括：

  • rax / eax / ax / al
  • rbx / ebx / bx / bl
  • rcx / ecx / cx / cl
  • rdx / edx / dx / dl
  • rsi / esi / si / sil
  • rdi / edi / di / dil
  • rbp / ebp / bp / bpl
  • rsp / esp / sp / spl
  • r8～r15及其32/16/8位形式

需要掌握：

  • r开头通常是64位；
  • e开头通常是32位；
  • ax/bx/cx/dx等是16位；
  • al/bl/cl/dl等是低8位；
  • 对32位寄存器的写操作，在x86-64中通常会把对应64位寄存器的高32位清零；
  • 对8位/16位寄存器的写操作通常只修改对应部分，不影响其他位。

考试中常见表述：

  • “将rax的高32位置0”；
  • “把32位结果写入eax”；
  • “符号扩展/零扩展传送到目标寄存器”。

这些都要结合寄存器宽度理解。

3.2 专用寄存器

重点掌握：

  • rip：程序计数器/指令指针，保存下一条要执行指令的地址；
  • rsp：栈指针，指向当前栈顶；
  • rbp：栈帧基址指针，常用于访问局部变量和参数；
  • rflags：标志寄存器，保存条件码和控制标志。

3.3 寄存器的作用

寄存器是CPU内部的高速存储单元，容量小、速度快。程序中的变量在机器级并不一定一直待在内存中：

  • 编译器会把频繁使用的变量放入寄存器；
  • 需要取地址的变量通常要放在内存中；
  • 函数参数和返回值通过约定好的寄存器传递；
  • 寄存器也可能保存临时计算结果、地址、循环变量等。

4. 内存、地址与数据表示

4.1 内存按字节编址

内存可以看作一个很大的字节数组：

  • 每个字节有一个地址；
  • 地址通常用十六进制表示；
  • 多字节数据存放在连续字节中；
  • 访问一个int通常访问4个字节，访问short访问2个字节，访问char访问1个字节。

要严格区分：

  • 地址：数据放在哪里，例如0x08004010；
  • 地址中的内容：该地址处存放的字节/数据；
  • 取地址：&x得到变量x的地址；
  • 解引用：*(int*)p表示把p当作地址，读取该地址处的内容。

考试中常见的“值是多少”与“地址是多少”必须分清。

4.2 小端序

x86通常采用小端序：

  • 多字节数据的低有效字节存放在低地址；
  • 高有效字节存放在高地址。

例如一个32位数据在内存中要按字节从低地址到高地址排列。具体题目中要结合变量地址、类型宽度和强制类型转换自行计算。

4.3 基本类型与符号性

必须掌握：

  • char：通常1字节；
  • short：通常2字节；
  • int：通常4字节；
  • long在x86-64 Linux中通常8字节；
  • 指针在x86-64中通常8字节；
  • float通常4字节；
  • double通常8字节。

有符号整数采用补码：

  • 正数与原码相同；
  • 负数按“取反加一”理解；
  • 符号扩展时高位补符号位；
  • 零扩展时高位补0。

4.4 指针与数组地址

要掌握：

  • 数组元素连续存放；
  • a在表达式中通常退化为首元素地址；
  • &a[0]是首元素地址；
  • a+1移动一个元素大小；
  • *(a+1)等价于a[1]；
  • 指针加法与所指类型大小有关；
  • 强制类型转换会改变“按什么类型解释”和“访问多少字节”。

例如：

  • (int*)(str+2)：先得到地址，再按int解释；
  • (char*)(&x+1)：先对&x做指针加法，再按char解释。

具体数值需根据地址和内存内容自行计算。

6. 栈与函数调用基础

6.1 栈的基本特点

x86栈通常：

  • 位于内存高地址区域；
  • 向低地址方向增长；
  • rsp指向当前栈顶；
  • push先减少rsp，再写入数据；
  • pop先读出数据，再增加rsp。

6.2 call与ret

call指令通常做两件事：

  1. 把返回地址压入栈顶；
  2. 把被调函数入口地址送入RIP。

ret指令通常：

  1. 从栈顶弹出返回地址；
  2. 把该返回地址送入RIP。

因此，函数调用能返回的关键是：返回地址保存在栈上。

6.3 栈帧

一个典型函数栈帧包括：

  • 调用者传递的参数；
  • 返回地址；
  • 保存的旧rbp；
  • 局部变量；
  • 保存的寄存器；
  • 临时空间。

7. RIP与控制流

7.1 顺序执行

顺序执行时：

  • CPU取出当前RIP指向的指令；
  • 执行后，RIP自动增加该指令的字节长度；
  • 下一条指令通常紧接在当前指令之后。

7.2 跳转

无条件跳转：

  • 直接修改RIP；
  • 例如jmp 目标地址。

条件跳转：

  • 根据标志寄存器中的条件码决定是否修改RIP；
  • 条件成立则跳到目标地址；
  • 条件不成立则继续执行下一条指令。

7.3 调用与返回

  • call：压返回地址，RIP改为被调函数入口；
  • ret：弹出返回地址，RIP改为返回地址。

7.4 中断与异常

中断和异常会打断正常控制流：

  • CPU保存必要现场；
  • 根据中断号/异常号查表；
  • 获得处理程序入口地址送入RIP；
  • 处理完后通过iret等恢复现场。

需要区分：

  • 中断：外部事件引起，通常在指令执行后检测；
  • 异常：执行指令过程中检测到，如除零、越界、缺页等；
  • Fault：处理后可能重新执行引起异常的指令；
  • Trap：处理后执行下一条指令，如系统调用；
  • Abort：严重错误，终止程序。

8. 标志寄存器与条件码

8.1 四个核心条件码

  • ZF：零标志。结果为0时ZF=1。
  • SF：符号标志。结果最高位为1时SF=1，表示负数。
  • CF：进位/借位标志。无符号运算溢出或借位时置位。
  • OF：溢出标志。有符号运算溢出时置位。

8.2 cmp与test

cmp a, b通常根据b - a设置条件码，但不保存结果。

test a, b通常根据a & b设置条件码，也不保存结果。

8.3 条件跳转

有符号比较常用：

  • jg：大于；
  • jge：大于等于；
  • jl：小于；
  • jle：小于等于；
  • je/jne：等于/不等于。

无符号比较常用：

  • ja：高于；
  • jae：高于等于；
  • jb：低于；
  • jbe：低于等于；
  • je/jne同样可用。

关键点：

  • 有符号和无符号不能混用跳转指令；
  • jg/jl看SF、OF、ZF；
  • ja/jb看CF、ZF；
  • 条件跳转是否发生，取决于执行跳转前标志寄存器的状态。

9. 指令、操作数与地址的关系

读汇编时要形成固定分析顺序：

  1. 这条指令访问寄存器还是内存？
  2. 操作数宽度是多少？8/16/32/64位？
  3. 源操作数和目的操作数分别是什么？
  4. 是否修改标志寄存器？
  5. 是否修改RIP？
  6. 是否访问栈？
  7. 执行后哪些寄存器/内存会变化？

尤其注意：

  • 地址与内容不同；
  • 寄存器宽度不同；
  • lea不访存；
  • mov可能访存；
  • cmp/test只设置标志；
  • add/sub等既产生结果又设置标志；
  • 条件跳转依赖标志，不直接比较两个变量。

10. 本章常见易错点

  1. 把地址当成内容：&x是地址，x是内容。
  2. 忽略小端序：多字节数据写内存时要低字节在低地址。
  3. 忽略类型宽度：char/short/int/指针访问字节数不同。
  4. 混淆符号扩展与零扩展：有符号转宽用符号扩展，无符号转宽用零扩展。
  5. 混淆逻辑右移与算术右移：无符号右移补0，有符号右移补符号位。
  6. 忘记栈向低地址增长：push使rsp减小。
  7. 忘记call压返回地址：返回地址在栈上。
  8. 忘记ret从栈顶取返回地址。
  9. 混淆rbp与rsp：rbp是栈帧基址，rsp是当前栈顶。
  10. 混淆lea与mov：lea算地址不访存。
  11. 混淆有符号/无符号跳转指令。
  12. 认为cmp保存结果：cmp只设置标志。
  13. 忽略32位写寄存器会清零高32位。
  14. 顺序执行时RIP增加的是指令长度，不是固定值。
  15. 中断/异常后RIP恢复位置取决于Fault/Trap类型。

3. 内存、地址与数据表示基础

3.1 内存按字节编址

内存可以看成一个很大的字节数组：

  • 每个字节有一个地址；
  • 地址通常用十六进制表示；
  • 多字节数据存放在连续字节中；
  • 访问char读1字节，short读2字节，int/float读4字节，指针/long在x86-64中通常读8字节。

必须严格区分：

  • 地址：数据放在哪里，例如&x；
  • 内容：该地址中存放的字节/数据，例如x的值；
  • 取地址：&x得到x的地址；
  • 解引用：*p表示把p当作地址，读取该地址处的内容。

题目中“&x = ...”给的是地址；“x = 10”给的是内容。

  • 字符串以'\0'结尾；
  • 字符数组初始化时，字符串字面量会逐字节复制，并通常带结尾'\0'。

填写字符串内存时：

  1. 按字符顺序写ASCII码；
  2. 注意字符串结尾的0x00；

  4. 若数组长度刚好或不足，要注意截断和是否有结尾符。

  1. 先算括号内地址表达式的值和类型；
  2. 强制转换成目标指针类型；
  3. 解引用时按目标类型读取相应字节数；
  4. 按目标类型解释这些字节；
  5. 注意小端序。

例如：

  • (int*)(str+2)：先算str+2这个地址，再按int*解释，解引用读取4字节并按int解释；
  • (char*)(&x+1)：先算&x+1，注意&x是int*，+1移动一个int大小，再转成char*，解引用读1字节。

这里的关键是：

  • 指针加法发生在强转之前；
  • 加法的步长由原指针类型决定；
  • 解引用读取的字节数由强转后的目标类型决定；
  • 不能把“地址值”和“该地址处的内容”混为一谈。

6. 变量与段/节

6.1 常见节

  • .text：可执行代码；
  • .data：已初始化的全局变量、静态变量；
  • .bss：未初始化或零初始化的全局变量、静态变量；
  • .rodata：只读数据，如字符串常量、const常量；
  • 栈：局部变量、函数调用信息；
  • 堆：动态分配内存。

6.2 局部变量

局部变量通常位于栈帧中：

  • 用-偏移(%rbp)表示；
  • 偏移在编译时确定；
  • 绝对地址在运行时由rbp决定；
  • 函数返回后栈帧失效，不能返回局部变量地址。

6.3 全局变量

全局变量定义：

  • 已初始化全局变量通常在.data；
  • 未初始化/零初始化全局变量通常在.bss；
  • 其地址在链接后相对固定；
  • 其他文件引用时会产生符号解析和重定位。

6.4 字符串常量

字符串字面量通常放在.rodata：

  • 只读；
  • 多处相同字面量可能被合并；
  • 通过地址引用；
  • 调用printf等函数时，字符串地址需要重定位/动态链接处理。

  3. 按小端序逐字节写；
  4. 字符串按ASCII逐字节写；
  5. 浮点按IEEE 754编码后小端写；
  6. 字符数组注意截断和结尾；
  7. 无关/填充字节填XX；
  8. 不要越界写到其他变量。

8.2 计算强制类型转换后的值

通用步骤：

  1. 先算地址；
  2. 再确定读取字节数；
  3. 从内存按小端序取出这些字节；
  4. 按目标类型解释；
  5. 有符号按补码，无符号按二进制，浮点按IEEE 754。

8.3 判断变量所在段

  • 局部变量：栈；
  • 已初始化全局：.data；
  • 未初始化全局：.bss；
  • 字符串常量：.rodata；
  • 函数代码：.text；
  • 动态分配：堆。

8.4 判断地址表达形式是否固定

  • 形式disp(%rbp)：偏移编译时固定；
  • 绝对地址运行时随rbp变化；
  • 全局变量地址链接后相对固定；
  • 数组元素地址 = 基址 + 索引×元素大小，索引运行时可变。

  4. 有符号/无符号扩展混用。
  5. 窄化转换忘记截断。
  6. 字符数组忘记结尾'\0'或截断规则。
  7. 浮点编码忘记阶码偏置127。
  8. 浮点尾数忘记隐含1。
  9. 指针加法步长用错类型大小。
  10. 强转发生在指针加法之前/之后搞错。
  11. 解引用读取字节数按原类型而不是目标类型。
  12. 把&a和a混为一谈。
  13. 忽略对齐和填充字节。
  14. 把局部变量偏移当成绝对地址。
  15. 认为局部变量地址在不同调用中固定不变。
  16. 把字符串常量放在.data而不是.rodata。
  17. 填写内存时把十进制直接写成十六进制字节。
  18. 未注意题目要求无关字节填XX。

第四章：异常控制流与程序执行原理

——中断、异常、系统调用、进程切换基础

本章对应试卷第一大题中“异常控制流下的RIP变化”以及“正常控制流 vs 异常控制流”的整体理解。第一章已经讲了正常控制流下RIP如何顺序变化、跳转、调用和返回；本章重点讲：当外部事件或指令执行错误打断正常控制流时，CPU如何保存现场、查表、转入处理程序，以及处理完后RIP恢复到什么位置。

1. 本章学习目标

学完本章应能：

  1. 区分正常控制流与异常控制流；
  2. 区分中断和异常：来源、同步性、检测时机；
  3. 掌握中断/异常处理的基本流程；
  4. 理解中断向量表/中断描述符表的作用；
  5. 理解CPU保存现场时保存哪些内容；
  6. 理解iret类指令恢复现场时大致恢复哪些内容；
  7. 掌握Fault、Trap、Abort三类异常及返回地址差异；
  8. 能判断某事件处理后是“重新执行当前指令”还是“执行下一条指令”；
  9. 理解系统调用为什么属于Trap；
  10. 理解用户态/内核态切换、进程上下文和进程切换基础；
  11. 理解异常控制流与RIP、栈、标志寄存器的关系；
  12. 能分析试卷中“按键操作、除零、越界、系统调用”等事件属于哪类控制流。

2. 总框架

本章可分成六块：

固定分析顺序：

  1. 事件是外部引起还是指令执行引起？
  2. 是异步还是同步？
  3. 是中断还是异常？
  4. 若是异常，属于Fault、Trap还是Abort？
  5. 处理完后RIP应指向当前指令还是下一条指令？
  6. 保存了哪些现场？返回地址在哪里？
  7. 是否需要特权级切换？
  8. 是否可能引发进程调度/切换？

3. 控制流的分类

3.1 正常控制流

正常控制流包括：

  • 顺序执行：RIP自动增加当前指令长度；
  • 条件跳转：满足条件时修改RIP；
  • 无条件跳转：直接修改RIP；
  • 函数调用：call压返回地址，RIP改为被调函数入口；
  • 函数返回：ret弹出返回地址送入RIP。

这些在第一章和第二章已经展开。

3.2 异常控制流

异常控制流是指程序执行过程中，由于外部事件或内部异常，CPU暂时打断当前程序，转去执行操作系统或处理程序，然后再决定是否返回原程序。

典型来源：

  • 外部设备中断：按键、时钟、网络包到达；
  • 指令执行异常：除零、缺页、越界、非法指令、断点；
  • 系统调用：程序主动请求操作系统服务；
  • 信号：操作系统向进程发送的软件事件。

异常控制流不是普通C语言中的if/goto，而是由CPU和操作系统协同完成的控制转移。

4. 中断与异常的区别

4.1 中断

中断通常由CPU外部事件引起：

  • 异步：不一定与当前指令同步；
  • 通常在指令执行后检测；
  • 例如按键、时钟中断、I/O完成；
  • 中断处理程序一般处理完外部事件后返回被打断程序继续执行；
  • 返回地址通常是下一条尚未执行的指令。

4.2 异常

异常通常由当前指令执行过程中检测到：

  • 同步：与当前指令相关；
  • 在指令执行过程中或执行后检测；
  • 例如除零、缺页、越界、非法指令、断点；
  • 处理程序返回地址取决于异常类型：
    • 可能重新执行引起异常的指令；
    • 可能执行下一条指令；
    • 也可能终止程序。

4.3 共同点

两者都属于异常控制流，通常都需要：

  • 保存现场；
  • 从用户态转到内核态或处理程序；
  • 根据中断号/异常号查找处理程序入口；
  • 处理完后恢复现场或终止程序。

4.4 易错点

  • 不要把“中断”和“异常”完全等同；
  • 按键、时钟通常属于中断；
  • 除零、越界通常属于异常；
  • 系统调用通常属于Trap，不是普通外部中断；
  • 缺页通常属于Fault，处理后重新执行当前指令；
  • 断点、系统调用通常属于Trap，处理后执行下一条指令。

5. 异常的分类

5.1 Fault：故障

Fault是异常处理程序处理后，可能重新执行引起异常的那条指令的异常。

典型：

  • 缺页异常：所需页面不在内存，操作系统调入页面后重新执行当前指令；
  • 某些可恢复的访问异常；
  • 段错误中部分情况可能终止，不一定恢复。

关键点：

  • 保存的返回地址通常指向引起异常的当前指令；
  • 处理成功后，RIP恢复为该指令地址，重新执行；
  • 若无法恢复，则终止进程。

5.2 Trap：陷阱

Trap是异常处理程序处理后，执行引起异常指令的下一条指令的异常。

典型：

  • 系统调用；
  • 断点指令；
  • 调试陷阱。

关键点：

  • 保存的返回地址通常指向下一条指令；
  • 处理完后继续执行下一条指令；
  • 系统调用是用户程序主动陷入内核的机制。

5.3 Abort：终止

Abort是严重错误，处理程序通常终止当前进程，不返回。

典型：

  • 硬件严重错误；
  • 不可恢复的异常；
  • 某些非法状态。

关键点：

  • 不保证恢复执行；
  • 可能终止进程或系统。

5.4 判断方法

遇到事件时问：

  1. 处理后是否需要重新执行当前指令？是→Fault；
  2. 是否执行下一条指令？是→Trap；
  3. 是否无法恢复、终止？是→Abort。

试卷中“除零”“越界”要结合具体体系结构和题目语境判断：它们首先都是异常；处理后若重新执行引起异常的指令，属于Fault类语义；若程序无法继续则可能终止。系统调用、断点通常作为Trap代表事件。

6. 中断/异常处理的基本流程

通用流程可概括为：

6.1 保存现场

CPU通常自动保存：

  • 标志寄存器，如EFLAGS/RFLAGS；
  • 返回地址，即CS:RIP或RIP；
  • 可能保存错误码；
  • 若发生特权级切换，还可能保存用户栈指针SS:RSP。

处理程序通常再保存：

  • 通用寄存器；
  • 可能保存其他现场。

注意：

  • CPU自动保存的内容和处理程序保存的内容要区分；
  • 返回地址可能指向当前指令或下一条指令，取决于中断/异常类型；
  • 标志寄存器保存是为了恢复条件码和控制标志。

6.2 查表

CPU根据中断号/异常号查找：

  • 中断向量表；
  • 中断描述符表IDT；
  • 异常表。

从中获得处理程序入口地址，送入RIP。

6.3 转入处理程序

处理程序开始执行后：

  • 可能保存通用寄存器；
  • 处理具体事件；
  • 可能修改进程状态、调度其他进程；
  • 最后恢复现场并返回。

6.4 恢复现场

iret类指令通常从栈中恢复：

  • 返回地址；
  • 代码段寄存器；
  • 标志寄存器；
  • 若特权级变化，还恢复栈指针和栈段。

不同体系结构、不同模式恢复顺序不同。考试中要按题目给出的体系结构和栈布局判断“先恢复什么、再恢复什么”，不要死背某一种顺序。

7. RIP在异常控制流下的变化

7.1 中断返回

对于外部中断：

  • 当前指令通常已经执行完；
  • 保存的返回地址通常是下一条尚未执行的指令；
  • 中断处理完后，RIP恢复为该返回地址，继续执行原程序。

7.2 Fault返回

对于Fault：

  • 保存的返回地址通常指向引起异常的当前指令；
  • 处理成功后，RIP恢复为当前指令地址；
  • CPU重新执行该指令；
  • 若再次失败，可能终止。

7.3 Trap返回

对于Trap：

  • 保存的返回地址通常指向下一条指令；
  • 处理完后，RIP恢复为下一条指令地址；
  • 程序继续执行。

7.4 Abort

对于Abort：

  • 通常不恢复执行；
  • 可能终止进程；
  • 不讨论正常RIP返回。

7.5 与call/ret的区别

  • call保存的是函数调用后的返回地址，转入函数；
  • ret从栈中弹出返回地址；
  • 中断/异常保存的是被打断程序的返回地址和标志寄存器；
  • iret恢复的不仅是RIP，还包括标志寄存器等；
  • call/ret是程序主动控制流，中断/异常是CPU/OS控制的异常控制流。

8. 系统调用

8.1 系统调用是什么

系统调用是用户程序请求操作系统内核服务的机制。

典型服务：

  • 文件读写；
  • 进程创建；
  • 内存分配；
  • 网络通信；
  • 程序退出。

系统调用通常通过特殊指令实现，例如：

  • int指令；
  • syscall指令；
  • sysenter等。

8.2 系统调用属于Trap

系统调用通常属于Trap：

  • 用户程序主动触发；
  • 从用户态陷入内核态；
  • 内核处理完后，返回到系统调用指令的下一条指令；
  • 返回值通常放在约定寄存器中。

8.3 用户态与内核态

系统调用涉及特权级切换：

  • 用户态权限受限；
  • 内核态可执行特权指令、访问受保护资源；
  • 系统调用是用户态进入内核态的合法入口；
  • 中断和异常也可能导致进入内核态。

8.4 系统调用与普通函数调用区别

  • 普通函数调用在同一特权级内，用call/ret；
  • 系统调用跨越用户态/内核态，用特殊指令；
  • 系统调用保存/切换栈、特权级和现场；
  • 系统调用返回地址通常是下一条指令；
  • 系统调用开销通常大于普通函数调用。

9. 进程与上下文切换基础

9.1 进程上下文

进程上下文包括：

  • 寄存器内容；
  • 程序计数器RIP；
  • 栈指针RSP；
  • 标志寄存器；
  • 页表基址等内存管理信息；
  • 打开文件、信号状态等内核数据结构。

9.2 进程切换

进程切换通常发生在：

  • 时钟中断触发调度；
  • 系统调用阻塞；
  • 异常导致进程终止；
  • 更高优先级进程就绪。

切换过程大致：

  1. 保存当前进程上下文；
  2. 选择下一个进程；
  3. 恢复下一个进程上下文；
  4. 切换页表、栈等；
  5. 返回用户态执行。

9.3 与异常控制流关系

中断、异常、系统调用都可能导致：

  • 进入内核；
  • 内核处理后决定是否调度；
  • 若调度，则发生进程切换；
  • 不一定每次中断都切换进程。

9.4 易错点

  • 中断处理不等于进程切换；
  • 系统调用不等于进程切换；
  • 进程切换需要保存/恢复上下文；
  • 用户态和内核态使用不同栈；
  • 返回用户态时恢复用户寄存器。

10. 信号与软件异常控制流

信号是操作系统向进程发送的软件事件，例如：

  • 终止信号；
  • 段错误信号；
  • 除零信号；
  • 定时器信号。

信号可由异常触发，也可由其他进程或内核发送。信号处理属于异常控制流的一种软件机制。

要点：

  • 信号处理可能打断正常控制流；
  • 进程可选择忽略、默认处理或自定义处理；
  • 某些信号不可忽略；
  • 信号处理与硬件中断/异常不同，但都属于控制流被打断的机制。

11. 与栈、RIP、标志寄存器的联系

异常控制流中，栈通常保存：

  • 返回地址；
  • 标志寄存器；
  • 可能错误码；
  • 若特权级切换，保存用户栈信息；
  • 处理程序保存的通用寄存器。

分析题目时注意：

  1. 返回地址是当前指令还是下一条指令？
  2. 标志寄存器何时保存、何时恢复？
  3. iret恢复顺序按题目体系结构判断；
  4. 用户栈和内核栈是否切换；
  5. 处理程序是否保存通用寄存器；
  6. 处理完后RIP恢复到哪个地址；
  7. 是否可能终止而不返回。

  2. 把按键操作当成异常而不是中断。

3. 存储层次与程序局部性

3.1 存储层次

典型层次：

越靠近CPU：

  • 容量越小；
  • 速度越快；
  • 成本越高。

程序性能很大程度取决于能否利用Cache，减少访问主存。

3.2 时间局部性

时间局部性：刚被访问的数据/指令，很可能在不久后再次被访问。

例子：

  • 循环变量反复使用；
  • 同一数组元素多次访问；
  • 函数内反复调用的指令。

优化利用：

  • 把频繁使用的变量放入寄存器；
  • 循环中复用已加载的数据；
  • 减少重复内存访问。

3.3 空间局部性

空间局部性：如果一个地址被访问，其相邻地址很可能很快被访问。

例子：

  • 顺序遍历数组；
  • 顺序执行指令；
  • 按行访问二维数组。

优化利用：

  • 顺序访问内存；
  • 按行优先遍历二维数组；
  • 分块提高Cache命中率；
  • 预取。

3.4 Cache与块

Cache按块/行加载数据：

  • 访问一个字节时，通常把整个Cache块调入；
  • 若程序随后访问相邻字节，可命中Cache；
  • 若访问跨度很大，可能每次缺失。

因此：

  • 顺序访问通常比跳跃访问快；
  • 行优先访问二维数组通常比列优先快；
  • 小工作集比大工作集更容易留在Cache中。

4.2 行优先遍历

内层循环访问连续地址，空间局部性好，Cache命中率高。

4.3 列优先遍历

内层循环每次跨一行，地址跳跃大，空间局部性差，Cache缺失多。

4.4 答题要点

问“行序优先访问为什么快，利用了CPU什么特性和二维数据存储什么特性”：

  • 利用了空间局部性和Cache；
  • 利用了二维数组行优先连续存储特性；
  • 行优先遍历访问地址连续，Cache命中率高；
  • 列优先遍历跨行跳跃，Cache命中率低。

5. 分支、流水线与无分支优化

5.1 流水线

现代CPU采用流水线：

  • 取指、译码、执行、访存、写回等阶段重叠；
  • 理想情况下每个周期完成一条指令；
  • 分支会导致控制冒险；
  • 分支预测失败需要清空流水线，代价较大。

5.2 分支预测

CPU会预测条件跳转方向：

  • 预测正确：继续流水；
  • 预测失败：流水线冲刷，损失若干周期；
  • 分支越难预测，性能损失越大。

5.3 无分支优化

将分支语句转换为无分支语句，可减少控制冒险和预测失败。

常见方法：

  • 条件传送cmov；
  • 位运算/掩码选择；
  • 算术技巧；
  • 编译器生成条件移动而不是跳转。

例如概念上：

可优化为条件传送，避免分支。

5.4 为什么提高速度

  • 减少分支指令；
  • 减少预测失败；
  • 减少流水线冲刷；
  • 提高指令级并行；
  • 使执行路径更可预测。

5.5 循环转无循环

将循环展开或完全展开，减少循环控制分支次数：

  • 减少比较和跳转；
  • 增加指令级并行；
  • 但可能增加代码体积和寄存器压力。

6. 循环优化

6.1 强度削弱

用较便宜的运算替代较昂贵的运算。

典型：

  • 乘法→移位/加法/lea；
  • 多次乘法→累加；
  • 数组下标乘法→指针递增。

例如：

  • imul $2, %eax可用add %eax, %eax或shl $1, %eax替代；
  • 乘2的幂可用移位；
  • lea可做简单乘加。

6.2 循环不变代码外提

把循环体内每次结果都相同的计算移到循环外。

例如：

若c*d不变，可先算一次再循环。

6.3 循环展开

减少循环控制开销：

  • 每次迭代处理多个元素；
  • 减少比较、跳转、计数器更新次数；
  • 增加指令级并行；
  • 可能提高寄存器压力。

6.4 减少内存访问

  • 用寄存器保存循环变量和累加器；
  • 避免重复从内存读取同一变量；
  • 指针遍历数组；
  • 合并重复访存。

6.5 循环交换

对二维数组，交换内外层循环以改善空间局部性，但必须保证语义等价。

6.6 分块

把大数组分成小块，使块内数据能留在Cache中，提高复用。

7. memset与批量置零

7.1 逐字节循环置零

问题：

  • 每次只写1字节；
  • 循环控制开销大；
  • 访存粒度小；
  • 分支多。

7.2 memset

memset是库函数，通常经过高度优化：

  • 按字/块写入；
  • 使用更宽存储指令；
  • 可能使用SIMD；
  • 减少循环次数；
  • 利用存储层次和指令级并行；
  • 编译器也可能内联优化。

7.3 为什么快

  • 减少循环控制；
  • 增大每次写入粒度；
  • 更好利用Cache和写缓冲；
  • 可能使用向量指令；
  • 减少分支和访存次数。

8. 与CPU特性无关的编译优化

常见优化：

  1. 常量折叠：编译时计算常量表达式；
  2. 常量传播：把已知常量替换到使用处；
  3. 公共子表达式消除：重复计算只算一次；
  4. 死代码消除：删除不会影响结果的代码；
  5. 代数化简：x+0、x*1、x*0等化简；
  6. 强度削弱：乘法替换为移位/加法；
  7. 循环不变代码外提；
  8. 函数内联；
  9. 控制流简化；
  10. 寄存器分配；
  11. 代码移动；
  12. 尾递归优化等。

答题时要区分：

  • 与CPU特性无关：代数化简、常量折叠、公共子表达式、死代码消除等；
  • 与CPU特性相关：利用流水线、分支预测、Cache、SIMD、指令级并行等。

9. 等价优化汇编程序段

9.1 分析步骤

  1. 先读懂原汇编完成什么功能；
  2. 找出可优化点：
    • 重复内存访问；
    • 重复计算；
    • 循环控制；
    • 可合并的乘加；
    • 可移出循环的不变量；

  4. 写出更少指令/更少访存/更少分支的版本；

9.2 常见优化策略

  • 用寄存器代替内存；
  • 用lea做乘加；
  • 用移位替代乘除2的幂；
  • 循环展开；
  • 强度削弱；
  • 减少重复加载；
  • 合并循环控制；
  • 消除无用指令。

9.3 注意

  • 不要改变溢出语义（除非题目允许）；
  • 不要改变有符号/无符号解释；
  • 数组访问要保证地址计算正确；
  • 循环边界和次数不能错；
  • 优化程序段要尽量简洁但正确。

10. 程序安全性

10.1 返回局部变量地址的问题

局部变量位于栈帧中：

  • 函数返回后栈帧失效；
  • 返回局部变量地址会产生悬空指针；
  • 调用者继续访问是未定义行为；
  • 后续函数调用可能覆盖该栈空间；
  • 应返回静态变量、全局变量、动态分配内存或调用者提供的缓冲区。

10.2 缓冲区溢出

缓冲区溢出：

  • 向缓冲区写入超过其容量的数据；
  • 覆盖相邻栈数据；
  • 可能覆盖局部变量、保存的rbp、返回地址、函数指针等；
  • 攻击者可劫持控制流。

  1. 栈保护/Canary：
    • 在返回地址前放哨兵值；
    • 函数返回前检查Canary是否被改；

  3. NX/DEP：
    • 栈不可执行；
    • 防止在栈上执行shellcode。
  4. 边界检查：

  • 插入栈保护Canary检查；
  • 使用安全函数/边界检查；
  • 插桩运行时检测；
  • 结合ASLR、NX等系统级防御。

  3. 忘记C数组行优先存储。
  4. 认为分支越多越好。
  5. 忘记分支预测失败会冲刷流水线。

3. 从源程序到可执行文件

3.1 基本流程

以C程序为例：

更概括地说：

  • 编译器负责把C语句翻译成汇编；
  • 汇编器把汇编翻译成机器码，生成可重定位目标文件；
  • 链接器把多个.o文件和库合并，确定最终地址，生成可执行文件。

3.2 可重定位目标文件

可重定位目标文件：

  • 代码和数据地址尚未最终确定；
  • 通常每个节从0开始有偏移；
  • 包含符号表和重定位信息；
  • 链接器可以把它与其他目标文件合并；
  • 常见扩展名.o。

可执行目标文件：

  • 已经完成符号解析和重定位；
  • 程序各节有最终虚拟地址；
  • 可以被加载器加载运行。

共享目标文件：

  • 动态共享库，如.so；
  • 可在加载时或运行时链接；
  • 常与位置无关代码相关。

3.3 链接器的主要任务

链接器主要做两件事：

  1. 符号解析：把每个符号引用与一个符号定义关联起来；
  2. 重定位：合并节，确定最终地址，修改引用处，使指令/数据指向正确地址。

4. 可重定位目标文件与常见节

4.1 ELF常见节

节 作用
.text 已编译程序的机器代码
.rodata 只读数据，如字符串常量、const常量、跳转表等
.data 已初始化的全局变量和静态变量
.bss 未初始化或零初始化的全局变量和静态变量；不占文件空间，运行时清零
.symtab 符号表，记录函数和全局/静态变量等符号信息
.rel.text .text节的重定位条目
.rel.data .data节的重定位条目
.debug 调试信息
.strtab 字符串表，存放符号名等字符串
.shstrtab 节名字符串表
.plt / .got 动态链接相关，过程链接表/全局偏移表

不同教材和平台可能有.rela.text、.rela.data，表示带显式加数的重定位节；原理相同。

4.2 .data与.bss

  • 已初始化全局变量：.data；
  • 未初始化或零初始化全局变量：.bss；
  • .bss只记录大小，不在目标文件中占实际数据空间，加载时清零；
  • 静态局部变量也类似全局变量，放在.data或.bss，但符号绑定可能是局部符号。

4.3 .rodata

.rodata存放只读数据：

  • 字符串字面量；
  • const全局变量；
  • switch跳转表；
  • 其他只读常量。

字符串常量通常放在.rodata，而不是.data。

4.4 .text

.text存放机器指令：

  • 函数代码；
  • 指令中引用全局变量、字符串地址、外部函数时，可能需要重定位；
  • 对.text中地址引用的重定位条目通常在.rel.text或.rela.text。

5. 符号与符号表

5.1 什么是符号

符号通常表示：

  • 函数名；
  • 全局变量名；
  • 静态变量名；
  • 外部引用名；
  • 节名等。

符号表记录符号的：

  • 名字；
  • 类型：函数、对象、节、文件等；
  • 绑定：局部、全局、弱全局；
  • 所在节；
  • 值/偏移；
  • 大小；
  • 可见性等。

5.2 全局符号与局部符号

  • 全局符号：可以被其他目标文件引用，如非static全局变量和非static函数；
  • 局部符号：只在本目标文件可见，如static函数、static全局变量；
  • 局部变量：函数内自动变量通常不进入全局符号表，它们位于栈帧中，由rbp/rsp偏移访问；
  • 调试信息中可能记录局部变量，但这不是链接符号。

5.3 未定义符号

如果当前目标文件引用了其他文件中定义的符号，而本文件没有定义，则符号表中可能有：

  • 未定义符号条目；
  • 链接时需要由其他目标文件或库提供定义；
  • 若最终找不到定义，链接器报“未定义引用”。

5.4 强符号与弱符号

常见规则：

  • 函数名和已初始化全局变量通常是强符号；
  • 未初始化全局变量在传统模型中可能是弱符号/COMMON符号；
  • 强符号不能重复定义；
  • 一个强符号和多个弱符号：选择强符号；
  • 多个弱符号：按规则选一个，可能选占用空间较大的；
  • 未定义符号最终必须有定义。

现代GCC常用-fno-common，未初始化全局变量也可能进入.bss并作为强符号处理。考试中要按题目所给模型判断。

5.5 符号解析

符号解析就是：

  • 对每个引用，找到唯一的定义；
  • 处理强符号、弱符号冲突；
  • 处理未定义符号；
  • 从静态库中按需提取成员。

5.6 静态库解析顺序

静态库.a是目标文件集合：

  • 链接器按命令行顺序扫描；
  • 只提取当前未解析符号所需的成员；
  • 若库成员之间有依赖，顺序可能重要；
  • 循环依赖可用--start-group等处理。

6. 重定位

6.1 为什么需要重定位

可重定位目标文件中：

  • 指令和数据地址尚未最终确定；
  • 编译器生成代码时，不知道全局变量、函数、字符串常量最终会被放在哪个地址；
  • 因此需要在指令中留下“占位”，并记录重定位信息；
  • 链接器最终确定地址后，修改这些位置。

6.2 重定位条目的基本内容

重定位条目通常包含：

  • 重定位偏移：需要修改的位置在节中的偏移；
  • 符号：引用的是哪个符号；
  • 重定位类型：如何计算最终值；
  • 加数/调整量：计算时的附加常量。

链接器根据符号最终地址和重定位类型，计算要写入指令/数据的值。

6.3 常见重定位类型

x86-64常见：

  • R_X86_64_32：32位绝对地址；
  • R_X86_64_32S：32位有符号绝对地址；
  • R_X86_64_64：64位绝对地址；
  • R_X86_64_PC32：32位PC相对地址；
  • R_X86_64_PLT32：对PLT入口的PC相对调用；
  • 动态链接还涉及GOT/PLT相关重定位。

不需要死背所有类型，但要理解：

  • 绝对地址重定位：最终地址直接填入；
  • PC相对重定位：目标地址与当前指令地址的差值填入；
  • 函数调用常使用PC相对调用；
  • 动态链接函数调用可能通过PLT。

6.4 哪些地方需要重定位

常见需要重定位的位置：

  1. 指令中引用全局变量地址；
  2. 指令中引用字符串常量地址；
  3. 函数调用引用外部函数；
  4. 数据中保存指针/地址；
  5. 跳转表中保存代码地址；
  6. 动态链接中的GOT/PLT条目。

不需要重定位的情况：

  • 纯寄存器运算；
  • 局部变量通过rbp/rsp偏移访问；
  • 同一节内已确定的相对跳转；
  • 已由编译器确定的栈帧偏移；
  • 立即数常量本身。

6.5 全局变量定义与重定位

对于：

通常：

  • 在.data中分配4字节，存放10；
  • 在.symtab中产生global符号条目；
  • 符号类型通常是对象；
  • 绑定通常是全局；
  • 记录所在节、大小、偏移；
  • 定义本身通常不需要重定位，因为初始值10直接写入.data；
  • 若初始值是另一个符号地址，则.data中可能需要重定位。

对于未初始化：

通常：

  • 进入.bss；
  • 符号表记录大小和节；
  • 不占文件数据空间。

6.6 全局变量引用与重定位

对于函数中：

通常：

  • temp是局部变量，位于栈帧，不进入全局符号表；
  • 读取global的指令在.text中；
  • 指令中需要填入global的地址或相对地址；
  • .symtab中可能有对global的引用/未定义条目，若本文件未定义；
  • .rel.text或.rela.text中产生重定位条目；
  • 链接时解析global地址并修改指令。

分析时要区分：

  • global的定义在哪个目标文件；
  • 当前文件是定义还是引用；
  • 引用指令是绝对寻址还是PC相对寻址；
  • 是否需要重定位。

6.7 字符串常量与重定位

对于：

通常：

  • 字符串"very good\n"放在.rodata；
  • .rodata中存字符字节和结尾\0；
  • 代码中需要把字符串地址传给printf；
  • 对字符串地址的引用需要重定位；
  • 对printf函数符号的调用也需要重定位/动态链接处理。

6.8 函数调用与重定位

调用外部函数如printf：

  • 代码中call printf需要确定printf地址；
  • 静态链接时链接器解析printf定义并重定位；
  • 动态链接时通常生成call printf@plt，通过PLT/GOT跳转；
  • 重定位可能针对printf符号或PLT入口；
  • 动态链接器在加载时填充GOT。

6.9 判断“有几处需要重定位”的方法

不要直接猜数字，按反汇编逐条看：

  1. 哪些指令引用了外部符号？
  2. 哪些指令引用了全局变量地址？
  3. 哪些指令引用了字符串常量地址？
  4. 哪些指令调用了外部函数？
  5. 哪些数据中保存了地址？
  6. 是否通过PLT/GOT？
  7. 每个引用位置在哪个节、偏移多少、针对哪个符号？

试卷问“printf语句对应的代码中有几处需要重定位、分别是什么位置”，需要根据实际汇编判断。通用知识点是：

  • 对printf函数符号的调用位置；
  • 对格式字符串地址的引用位置；
  • 动态链接时可能涉及PLT/GOT相关重定位；
  • 参数传递本身若是立即数/寄存器，不一定需要重定位。

7. 链接过程

7.1 两个主要阶段

链接过程可概括为：

更细：

  1. 链接器读取各个可重定位目标文件；
  2. 把相同节合并，如所有.text合并，所有.data合并；
  3. 为合并后的节分配最终虚拟地址；
  4. 符号解析：建立全局符号表，解析引用；
  5. 重定位：根据符号最终地址修改引用处；
  6. 生成可执行目标文件；
  7. 可执行文件包含程序头，加载器据此加载。

7.2 符号解析细节

  • 每个目标文件有符号表；
  • 全局符号进入全局符号表；
  • 局部符号只在本地处理；
  • 未定义符号等待其他文件/库定义；
  • 强符号冲突报错；
  • 弱符号按规则处理；
  • 静态库按需提取。

7.3 重定位细节

  • 合并节后，每个节有最终地址；
  • 每个重定位条目指向节中某个偏移；
  • 链接器计算符号最终地址；
  • 按重定位类型计算写入值；
  • 修改指令或数据；
  • 最终可执行文件中不再需要这些重定位条目，除非动态链接。

7.4 可执行文件加载

可执行文件有程序头表，描述：

  • 哪些段需要加载；
  • 虚拟地址；
  • 文件偏移；
  • 权限：读/写/执行；
  • 入口地址。

加载器把可执行文件映射到进程地址空间，设置RIP到入口，开始执行。

8. 链接时能检测到的错误

8.1 未定义符号/未定义引用

如果某个符号被引用，但所有目标文件和库都没有定义：

  • 链接器报“undefined reference”；
  • 例如调用了未实现的函数，或引用了未定义全局变量；
  • 这是典型链接错误。

8.2 多重定义

如果多个目标文件都定义了同一个强符号：

  • 链接器报“multiple definition”；
  • 函数和已初始化全局变量通常不能重复定义；
  • 弱符号可能不报错，按规则选择。

8.3 静态库成员缺失

如果静态库中没有提供所需符号：

  • 报未定义引用；
  • 库顺序不对也可能导致未解析。

8.4 重定位相关错误

某些情况下可能出现：

  • 重定位溢出；
  • 地址无法表示；
  • 架构不兼容；
  • 目标文件格式错误。

8.5 链接时检测不到的错误

链接器通常检测不到：

  • 数组越界；
  • 空指针解引用；
  • 逻辑错误；
  • 类型不匹配的某些情况，可能只警告；
  • 缓冲区溢出；
  • 运行时除零；
  • 动态库版本不匹配可能在加载/运行时才发现。

要区分：

  • 编译错误：语法、类型等；
  • 链接错误：符号解析、重定位；
  • 运行时错误：越界、空指针、除零等。

8.6 强符号/弱符号与错误

  • 两个强符号同名：错误；
  • 强符号+弱符号：选强符号；
  • 多个弱符号：通常不报错，选一个；
  • 未定义符号：错误，除非动态链接在运行时解析。

9. 静态链接与动态链接

9.1 静态链接

静态链接：

  • 在生成可执行文件时把所需库代码复制进来；
  • 可执行文件包含库代码；
  • 运行时不再需要对应静态库；
  • 文件较大；
  • 库更新需要重新链接；
  • 符号解析和重定位在链接时完成。

静态库：

  • .a文件；
  • 是目标文件集合；
  • 链接器按需提取成员；
  • 只提取被引用的成员。

9.2 动态链接

动态链接：

  • 可执行文件不包含共享库完整代码；
  • 运行时由动态链接器加载共享库；
  • 多个进程可共享同一库代码；
  • 文件较小；
  • 库更新可能无需重新链接；
  • 启动/运行时有一定开销；
  • 需要处理位置无关代码、GOT/PLT、符号解析。

共享库：

  • .so文件；
  • 可被多个进程映射；
  • 通常编译为位置无关代码PIC；
  • 动态链接器在加载时进行重定位。

9.3 PLT与GOT

动态链接中常见：

  • GOT：全局偏移表，存放外部符号的最终地址；
  • PLT：过程链接表，为外部函数调用提供跳转桩；
  • 第一次调用可能触发动态链接器解析，之后通过GOT直接跳转；
  • 代码中使用call printf@plt，而不是直接call printf。

9.4 位置无关代码

位置无关代码PIC：

  • 代码不依赖固定加载地址；
  • 通过PC相对寻址和GOT访问外部符号；
  • 共享库通常要求PIC；
  • 现代可执行文件也常用PIE。

9.5 动态链接器

动态链接器：

  • 加载共享库；
  • 解析动态符号；
  • 重定位GOT条目；
  • 处理依赖关系；
  • 最后把控制权交给程序入口。

动态链接错误可能在：

  • 加载时发现找不到共享库；
  • 运行时发现未定义动态符号；
  • 版本不匹配。

10. 链接与地址、节、符号的综合分析

遇到链接题，可以按下面模板分析：

10.1 变量定义

例如：

问“可重定位目标文件中哪些节会生成与该定义有关的信息”：

  1. 数据放在.data；
  2. 符号表.symtab中有global条目；
  3. 若初始值只是常量，通常不需要重定位；
  4. 若初始值涉及地址，.data可能需要重定位；
  5. 未初始化则放.bss。

10.2 变量引用

例如：

问“哪些节会生成与该语句有关的信息”：

  1. 读取global的指令在.text；
  2. 指令中引用global地址，需要在.rel.text/.rela.text中产生重定位；
  3. .symtab中可能有global引用/未定义条目；
  4. temp是局部变量，通常在栈帧，不进入全局符号表；
  5. 若global在其他文件定义，当前文件符号表中是未定义引用。

10.3 字符串常量

问“字符串存什么节”：

  • 通常.rodata；
  • 只读；
  • 以\0结尾；
  • 代码中引用其地址需要重定位。

10.4 外部函数调用

问“调用printf有几处重定位”：

  1. 找调用printf的指令；
  2. 找格式字符串地址引用；
  3. 看是否通过PLT/GOT；
  4. 看参数中是否还有其他外部地址；
  5. 每个引用位置对应一个重定位条目；
  6. 具体数字按反汇编判断。

10.5 链接错误

问“链接时能检测到什么错误”：

  • 未定义引用；
  • 多重定义强符号；
  • 静态库缺失；
  • 重定位溢出/格式错误；
  • 不能检测运行时越界、逻辑错误等。

11. 本章常见易错点

  1. 把全局变量定义放在.text。
  2. 把字符串常量放在.data而不是.rodata。
  3. 认为未初始化全局变量在.data而不是.bss。
  4. 认为局部变量会进入全局符号表。
  5. 把局部变量和静态局部变量混淆。
  6. 认为所有符号都需要重定位。
  7. 认为定义全局变量一定需要重定位。
  8. 忽略“引用”和“定义”的区别。
  9. 忘记函数调用外部符号需要重定位。
  10. 忘记字符串地址引用需要重定位。
  11. 把编译错误、链接错误、运行时错误混淆。
  12. 认为链接器能检测数组越界。
  13. 认为弱符号重复一定报错。
  14. 忽略强符号/弱符号规则。
  15. 把静态链接和动态链接的时机混淆。
  16. 认为动态链接不需要重定位。
  17. 忘记PLT/GOT的作用。
  18. 认为共享库一定复制进可执行文件。
  19. 忽略PIC和PC相对寻址。
  20. 分析重定位处数时不看实际汇编，直接猜数字。
